### CI failure patterns (21 failed Pipeline runs, all fixed before the merge or by #375)

Each pattern below gets a process rule, proposed as `_bmad/custom/bmad-build.toml` facts in A3-A9.

- **C1. Hand-injected e2e rows miss a column that a parser now requires.** `layout.spec.ts` widens the grid by appending team rows to the calendar's answer in the browser. 0080 made `off_on_holidays` a required field in `teamRowOf`, so the injected rows made the whole calendar unavailable: five `layout.spec.ts` cases failed in run 45756975501, fixed by `523deb7`. 21.20 (`minimum_members`) avoided the same failure only because its spec listed the injected rows by hand (`spec-21-20…md:71`). 21.18 had to reason it out too (`spec-21-18…md:37`, `:109`). Each new team column is one more manual step, and nothing enforces it. → A3.
- **C2. An RLS policy that reads its own table recurses (42P17).** 0079's insert and delete policies on `member_schedule_versions` selected from the same table under RLS. Every write failed, and the claimless and suspended sweeps failed downstream (run 45729190376: `expected '42P17' to be '42501'`). Fixed by `e2066ff` with two `private` definers on 0064's pattern (`spec-21-10…md:95`). The scaffold pin added then covers that one table only. → A4.
- **C3. A plpgsql alias `old` collides with the trigger's OLD record.** `private.relink_resolution_to_assignment()` aliased `personal_assignments` as `old`. Every insert into `personal_assignments` failed with `column reference "old.organization_id" is ambiguous`, and 0077's save failed with it (run 45766452468). Fixed by `42f386b`, which also added a DB-free scaffold guard against aliasing `old`/`new`. The guard exists, but no build fact names it. → A5.
- **C4. Catalog inventories assert the wrong order.** `concurrent-writes`' trigger inventory reads `tgattr`'s columns ordered by `attname`. 0082's widened triggers therefore answer `archived, minimum_members, off_on_holidays`, not the order the migration declares (run 45777662906, fixed by `979fb10`). The same class came up in 21.7's review, where provisioning's sorted FK list had a key out of order (`spec-21-7…md:107`). 21.12's `name-key` constraint lists missed the new `job_roles_*` constraints (run 45682797678), and 21.2's audited-table count missed one (run 45635044800). All four are hand-maintained catalog pins that only CI's database job checks. → A6.
- **C5. React StrictMode's effect replay closes a dialog opened on mount.** `useMemberTeam` and `useMemberScheduleSource` reset their dialogs in an effect keyed on the member id. StrictMode replays a fresh mount's effects, so *Timovi i raspored*'s host, which opened the dialog in the mount commit, had it closed before any render. Run 45804339616 failed, and the first fix (`def7964`) "was right but not the cause", so run 45807411097 failed too (`spec-21-26…md:99-105`). The unit tests do not render under StrictMode, so only the e2e on the dev server found it. → A7.
- **C6. Two stories that were each green broke `main`'s typecheck once both merged.** #373 (21.9) changed `personalShiftOn`'s signature and #374 (21.6) merged 16 minutes later with a three-argument call. `main`'s push run 45700921781 failed `Typecheck` (`day-detail.ts(324,19): error TS2554: Expected 4 arguments, but got 3`), and #375 (`7ddc632`) fixed it. 21.25 had made the same fix on its branch and dropped it as a duplicate (`spec-21-25…md:93`). → A8.
- **C7. The shared e2e organization exceeded the history export limit.** The run's organization collects every spec's history. On PR #387 it reached 2,078 rows, past the export's 2,000-row limit, so `history.spec.ts:137` saw the export's own refusal instead of the PDF writer's failure alert (run 45834966836, fixed by `b9f4254` by narrowing to the fixture's team). Each new epic adds rows, so any other case that reads organization-wide history or totals is exposed the same way. → A9.
- **C8. Smaller patterns, each fixed once.** Taken together, every one of them is a pin or test that missed a change made elsewhere:
  - ShellCheck on the landing probe (45677842651, `43afe08`);
  - `localization-applied`'s SOURCES missing a new page (45674578672);
  - `e2e-plural` still expecting *smjene* after the rename (45635097029, `48b39d8`);
  - a Playwright `has:` locator rooted at the grid (45724396071, 64 cases);
  - `*Postavke*` pinned as two links (45804339616);
  - reminder leads above 0069's maximum (45731672725, `97c2d71`).

  The DB-free root tests that run locally caught none of them, because they are DB-connecting tests, e2e or lint. Disposition: accept. The existing rules ("A change to what a surface shows greps e2e", "DB-free root tests run locally") cover these in principle.
- **C9. Flakes.** These failed and then passed with no fix:
  - `leave.spec.ts:260` (45695288965);
  - `kalendar-na-mobitelu.spec.ts:58` (502 instead of 404), and `layout.spec.ts:224` passed on retry (45834966836);
  - `answer-swap.spec.ts:165`, whose failure was the 60 s rotation-lock wait held by 21.7's failing case (`spec-21-8…md:97`);
  - 21.8's shard 1, cancelled at the 30-minute limit with no log kept (`spec-21-8…md:84`).

  Disposition: defer to the e2e sweep owner. The lock-holder cascade is the one worth a guard (A9's note).
